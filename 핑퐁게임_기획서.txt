────────────────────────────────────────────────────────────────
1. 개요
────────────────────────────────────────────────────────────────

1.1 한 줄 소개
    브라우저에서 바로 실행되는 1인용 클래식 핑퐁(Pong) 게임.
    플레이어(왼쪽)가 컴퓨터 AI(오른쪽)와 7점 선취제로 대결한다.

1.2 기획 의도
    - 설치·빌드·서버 없이 HTML 파일 하나로 즉시 플레이 가능할 것
    - 규칙은 3초 안에 이해되지만, 실력에 따라 결과가 갈릴 것
    - 랠리가 길어질수록 긴장이 고조되는 구조를 물리로 구현할 것

1.3 타깃
    - 짧은 시간(1판 약 1~3분) 안에 즐길 거리를 찾는 캐주얼 사용자
    - PC 마우스/키보드 사용자 및 모바일 터치 사용자 모두

1.4 플랫폼
    - 최신 데스크톱/모바일 브라우저 (Chrome, Edge, Safari, Firefox)
    - 오프라인 동작 (네트워크 요청 없음)


────────────────────────────────────────────────────────────────
2. 핵심 게임 규칙
────────────────────────────────────────────────────────────────

2.1 승리 조건
    - 먼저 7점을 획득한 쪽이 승리 (WIN_SCORE = 7)
    - 상대 진영 뒤쪽 라인을 공이 통과하면 1점 획득

2.2 진행 흐름
    - 득점이 발생하면 실점한 쪽을 향해 서브 (반격 기회 부여)
    - 서브 전 0.8초 카운트다운, 게임 시작 시에는 1.0초
    - 카운트다운 중에도 양쪽 패들은 자유롭게 이동 가능

2.3 랠리 가속
    - 패들에 공이 맞을 때마다 공 속도 ×1.045 (SPEED_GAIN)
    - 속도 상한 1150 px/s (MAX_BALL_SPEED)
    - 약 25회 반사 후 상한에 도달 → 무한 가속으로 인한
      조작 불능 상태를 방지

3. 조작
────────────────────────────────────────────────────────────────

    입력 수단          동작
    ─────────────────  ──────────────────────────────────────
    마우스 이동         패들이 커서를 부드럽게 추종 (보간)
    터치 / 드래그       동일 (모바일)

    * 키 입력이 있으면 마우스 추종보다 키 조작이 우선한다.
      (마우스를 놓아둔 채 키보드로 조작할 때 패들이 끌려가지 않도록)


────────────────────────────────────────────────────────────────
4. 난이도 설계
────────────────────────────────────────────────────────────────

4.1 난이도별 파라미터

    난이도    AI 속도    AI 오차폭   초기 공속도   설계 의도
    ────────  ─────────  ──────────  ───────────  ─────────────────
    쉬움      300 px/s    ±92 px      330 px/s     조작 익히기
    보통      420 px/s    ±58 px      390 px/s     기본 대전
    어려움    560 px/s    ±26 px      450 px/s     속도로만 실책
    불가능    900 px/s    ±4 px       520 px/s     사실상 무결점

4.2 난이도 조절의 원리
    AI는 공의 낙하 지점을 벽 반사까지 포함해 정확히 예측한다.
    따라서 난이도는 "예측을 못 하게" 만드는 것이 아니라,
    예측 지점에 무작위 오차를 더해 조절한다.

    패들 반높이가 48px이므로, 오차의 절댓값이 48px을 넘을 때만
    실제로 공을 놓친다. 오차폭이 W일 때 실책 확률은

        P(실책) = (W - 48) × 2 / (2W)     (W > 48인 경우)

    이 식에 따라 쉬움 ≈ 48%, 보통 ≈ 17%의 실책률이 나오도록
    오차폭을 역산해 설정했다.

    어려움·불가능은 오차폭이 48px 미만이라 오차만으로는 절대
    놓치지 않으며, 오직 "패들 이동 속도가 공을 따라가지 못할 때"만
    실점한다. 즉 난이도가 올라갈수록 실책의 성격이
    '우연'에서 '한계'로 바뀐다.

4.3 오차 갱신 시점
    - AI가 공을 쳐낸 순간
    - 새 서브가 시작된 순간 (첫 리턴도 완벽하지 않도록)
    한 번 정해진 오차는 다음 갱신까지 유지되므로, 플레이어가
    "AI가 이번엔 조금 위로 치우쳐 있다"를 읽고 대응할 수 있다.

5. 물리 명세
────────────────────────────────────────────────────────────────

5.1 필드 규격 (내부 좌표계)
    - 캔버스        900 × 560 px (화면 크기에 맞춰 비율 유지 스케일)
    - 패들          12 × 96 px, 좌우 벽에서 26px 안쪽
    - 공            반지름 8 px

5.2 패들 반사 각도
    공이 패들의 어느 지점에 맞았는지에 따라 반사각이 결정된다.

        rel   = (공 y − 패들 중심 y) / (패들 높이 / 2)   → −1 ~ +1
        angle = rel × 56.25°                            (π / 3.2)

    - 패들 정중앙 → 수평에 가깝게 빠르게 반사
    - 패들 끝 → 최대 56.25°로 크게 꺾임
    이로써 단순 반사가 아닌 "각도를 만들어 공격하는" 플레이가 가능하다.
    반사 직후 공을 패들 표면 밖으로 밀어내 끼임을 방지한다.

5.3 벽 반사
    - 상/하 벽에서 y축 속도 반전, 위치를 벽면에 스냅
    - 좌/우는 벽이 아닌 득점 라인

5.4 터널링 방지 (중요)
    공의 최고 속도가 1150 px/s이므로 60fps 기준 한 프레임에
    약 19px을 이동한다. 패들 두께는 12px이라 단순 이동 처리로는
    공이 패들을 통과해 버린다.

    이를 막기 위해 매 프레임의 이동을 여러 하위 스텝으로 쪼갠다.

        스텝 수 = ceil( |vx × dt| / (공 반지름 × 0.8) )

    한 스텝의 이동량이 6.4px을 넘지 않으므로 어떤 속도에서도
    패들을 건너뛰지 않는다.

5.5 프레임 시간 보정
    dt를 0.033초(약 30fps)로 상한 처리한다. 탭 전환이나 순간
    렉으로 프레임 간격이 벌어졌을 때 공이 순간이동하는 현상을 막는다.

5.6 서브 각도
    수평에 가까운 지루한 서브를 막기 위해 최소 각도를 보장한다.
        |angle| ∈ [0.12, 0.40] rad, 위/아래 방향은 무작위


────────────────────────────────────────────────────────────────
6. AI 알고리즘
────────────────────────────────────────────────────────────────

6.1 낙하 지점 예측 (predictBallY)
    공이 AI 쪽으로 올 때만 예측을 수행한다.
    현재 위치·속도에서 시작해, 다음 두 사건 중 먼저 오는 것을
    반복적으로 처리하며 목표 x에 도달할 때까지 전진시킨다.

        (a) 목표 x(패들 표면)에 도달
        (b) 상/하 벽에 충돌 → vy 반전

    벽 반사를 포함한 정확한 도착 y를 얻는다. 무한 루프 방지를 위해
    반복 500회 상한을 둔다.

6.2 복귀 행동
    공이 플레이어 쪽으로 향하는 동안(vx ≤ 0)에는 예측하지 않고
    필드 중앙(y = 280)으로 복귀한다. 다음 공격을 준비하는
    자연스러운 움직임을 만들면서, 동시에 AI가 항상 최적 위치에
    붙어 있지 않게 해 플레이어에게 각도 공격의 여지를 준다.

6.3 이동
    목표 지점을 향해 난이도별 최대 속도로 이동하되, 남은 거리가
    한 프레임 이동량보다 작으면 정확히 목표에 정렬한다.
    (떨림 현상 방지)

8. 연출 및 사운드
────────────────────────────────────────────────────────────────

8.1 시각 연출
    - 공 잔상 : 최근 14프레임 위치를 점점 작고 투명하게 렌더
    - 파티클 : 득점 시 18개 입자가 중력을 받으며 흩어짐
               (플레이어 득점 초록 / 실점 빨강)
    - 화면 흔들림 : 패들 타격 0.07초, 득점 0.22초
    - 공 글로우 : 그림자 블러로 발광 효과

8.2 사운드 (WebAudio, 외부 파일 없음)
    상황            주파수    파형        길이
    ──────────────  ────────  ──────────  ──────
    플레이어 타격    520 Hz    square      0.05s
    AI 타격          400 Hz    square      0.05s
    벽 반사          300 Hz    triangle    0.03s
    플레이어 득점    660 Hz    sine        0.18s
    플레이어 실점    180 Hz    sine        0.18s

    - 오디오 컨텍스트는 최초 재생 시 생성 (브라우저 자동재생 정책 대응)
    - 버튼으로 전체 음소거 가능
    - 오디오 미지원 환경에서는 예외를 삼키고 게임은 정상 진행

10. 검증 결과
────────────────────────────────────────────────────────────────

10.1 검증 방법
    DOM과 Canvas 컨텍스트를 스텁으로 대체하고 Node.js에서
    게임 루프를 헤드리스로 구동했다. 렌더링 호출(ctx.arc)을
    가로채 공의 좌표를 추출하고, 그 좌표를 그대로 포인터 입력으로
    되먹여 "실수하지 않는 완벽한 플레이어"를 시뮬레이션했다.
    난이도별 10분(36,000프레임)씩 실행.

10.2 결과

    난이도    완료 게임   최고 랠리   최장 정지 구간
    ────────  ──────────  ──────────  ───────────────
    쉬움         6판          24        1.00s (서브 대기)
    보통         1판         108        1.00s
    어려움       0판           —        1.00s
    불가능       0판           —        1.00s

10.3 확인된 사항
    - 공의 x 좌표가 46~854 범위를 벗어나지 않음
      → 패들을 통과하는 터널링 없음 (패들 표면 38 / 862 + 반지름 8)
    - 정지 구간이 서브 카운트다운 1.0초를 초과하지 않음
      → 공이 끼거나 멈추는 현상 없음
    - 10분 연속 구동 중 예외 발생 없음

10.4 밸런싱 이력
    초기 설정에서는 '보통' 난이도 AI의 오차폭이 ±34px이었다.
    이는 패들 반높이 48px보다 작아 AI가 오차만으로는 결코
    실책하지 않았고, 그 결과 완벽 플레이어 상대로 10분간
    단 한 점도 나지 않는 교착이 발생했다.
    4.2절의 실책 확률 식을 기준으로 오차폭을 재산정해
    (쉬움 60→92, 보통 34→58, 어려움 16→26) 게임이 정상적으로
    종료되도록 수정했다.

    '어려움'과 '불가능'의 무득점은 의도된 결과다. 이 두 난이도는
    실수하지 않는 가상 플레이어를 상대로 버티도록 설계되었으며,
    실제 사람이 플레이하면 정상적으로 점수가 발생한다.
